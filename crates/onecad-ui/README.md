# Native OneCAD host

This macOS host uses the shared application services, interaction reducer, checked
CPU scene and renderer. It implements the first prepared-profile workflow:
viewport profile selection, new extrusion preview and commit, applicable typed numeric
feature edits, world-plane and planar-face sketch entry and existing sketch editing with line/rectangle/circle
batches, scoped sketch undo/redo, finish/discard, body Move / Rotate, model undo/redo, save, and reopen of the saved copy. Build and automated
tests do not establish native input, appearance, accessibility or workflow acceptance.

The [native sketch and extrusion editing contract](../../docs/design/native-sketch-editing.md)
defines selection, input ownership, dimension authorship and admission behavior.
The tool pill and sketch visit actions use bounded horizontal scrolling when their
contents exceed the available lane. Their placement excludes side panels and
viewport controls; at the minimum window size, sketch visit actions move below
the camera controls. Pure egui layout tests cover light and dark themes at 1×
and 2× scale in minimum, default and larger windows. Native appearance and physical
input remain separate qualification lanes.

From the workspace root, `make build` builds/stages the OCCT sidecar, creates a
synthetic constrained plate fixture on first use, and builds the Rust desktop
target (`onecad-ui`). `make run` only launches the existing app and worker; it
never invokes Cargo, rebuilds the worker or generates fixtures. Missing build
outputs produce an error with instructions to run `make build`. Subsequent runs
reopen the saved QA copy. It uses
`/private/tmp/onecad-rust-desktop` for isolated data and logs. The initial fixture
is generated by the real-worker modeling regression; it is a development sample,
not a product document. OCCT must already be installed at
`$HOME/.onecad-occt/8.0.1`, or set `OCCT_ROOT`.

Use `make dev` to build, then run. The launch waits for a successful build even
with parallel Make.

Override `QA_ROOT`, `FIXTURE`, `DOCUMENT`, `WORKER_BUILD_DIR`, `WORKER`, `TARGET_DIR`,
or `APP_BINARY` with Make variables as needed. `TARGET_DIR` defaults to
`CARGO_TARGET_DIR` when set, otherwise the repository's `target` directory.
`DOCUMENT` must be a `.onecad` file in temporary storage,
because this host still enforces QA isolation. For example:

```sh
make build
make run QA_ROOT=/private/tmp/onecad-my-render-check
```

Build from the workspace root:

```sh
CARGO_TARGET_DIR=/private/tmp/onecad-native-rust-check \
CARGO_BUILD_JOBS=3 CARGO_PROFILE_DEV_DEBUG=0 CARGO_INCREMENTAL=0 \
  cargo build -p onecad-ui
```

The host requires an explicitly isolated temporary profile. Omit `--open` to
start a blank document and Home screen, or provide a prepared `.onecad` fixture.
Set the environment before launching the built binary; it never changes
process environment after threads start. Example paths below are synthetic QA
paths, not production document or application-data locations:

```sh
TMPDIR=/private/tmp/onecad-native-profile/temporary \
ONECAD_LOG_DIR=/private/tmp/onecad-native-profile/logs \
ONECAD_LIBRARY_ROOT=/private/tmp/onecad-native-profile/data/library \
ONECAD_WORKER_PATH="$PWD/worker/build-native-migration/onecad-worker" \
  /private/tmp/onecad-native-rust-check/debug/onecad-ui \
  --qa-root /private/tmp/onecad-native-profile \
  --open /private/tmp/onecad-273-qa/constrained-plate-80x50.onecad
```

The binary creates its dedicated directories before application startup. It
rejects production roots, unmarked shared directories and symlink escapes, and
holds an exclusive profile lock. The source fixture is copied to `documents/`.
To reopen saved work, pass that copied path with `--open`; an existing copy is
never overwritten from its original fixture. Settings, recents, autosave,
recovery, library, temporary imports and logs stay in this profile. Shared data
continuity remains outside this host's current scope.

Startup discovers crash recovery before opening the prepared saved document. Each
offer requires Restore, Open saved (which explicitly discards that recovery copy),
or Discard recovery. Restoring or opening one document enters the editor; other
offers stay protected for the next startup, rather than replacing unsaved recovered
work with another document. Closing the host before a decision preserves pending offers.
Restore keeps the recovered document dirty and uses the shared service's ownership
marker and autosave mutation notification, so a second crash retains the recovered
work. Saves stay under the isolated profile's `documents/`: an unavailable or
out-of-profile original path uses `recovered-<document UUID>.onecad` instead.
File actions use asynchronous native dialogs and typed requests on the bounded
service actor. New/Open/Import ask how to handle dirty work before replacement;
Save As and export stay within the QA `documents/` directory. External projects
open as unique bounded copies, while STEP import uses shared application services.
The File menu exports STEP, STL, OBJ and 3MF. Recents come from application metadata
inside this profile; no example projects or synthetic thumbnails are shown.
Cancellation and failed replacement preserve the current runtime. Save-before-close
continues only after a clean save, and blocks further authoring while pending.
Recovered documents with an out-of-profile path require Save As into QA storage.

Document identity, runtime session, revision, dirty state, title and path travel
through a bounded lifecycle slot independently of scene capture. Restore, import
and Save refresh this state before attempting geometry capture. A failed capture
therefore keeps Save available and dirty replacement/Quit prompts active, even
without a display. Title and path are bounded presentation copies; Save uses the
runtime's complete path. An ordinary dirty close preserves existing recovery and
releases its marker ownership without dropping labels. Only a clean durable Save
or explicit session-fenced Discard permits cleanup of dirty recovery. Discovery
never deletes recovery containers because of age. Ordinary close does not force
a fresh autosave; the existing autosave cadence still bounds captured changes.

STEP import stages a production worker, waits at most 8 seconds for its handshake,
and only then probes the source. The staged guard retains that exact worker's
readiness and import interface. Timeout, probe failure, or cancellation restores
prior services only while the guard still owns the stage. Publication and commit
check that owner atomically; replacement, close, and shutdown invalidate it.
An old import cannot publish over or roll back a newer owner. The native actor
serializes file intents. Other application New/Open/Recover callers still share
global displaced-backend bookkeeping: concurrent replacement through those APIs
remains unqualified and is not production writer-ownership support.

The ignored `typed_real_worker_import_export_roundtrip_preserves_document` host
test checks STEP round-trip topology, mass and centroids, binary STL records, OBJ
indices, and 3MF archive parts and mesh indices through typed file intents. It
also checks export leaves document/history/dirty state unchanged and cancelled or
failed import leaves the prior runtime and worker intact. Run it with
`ONECAD_REQUIRE_WORKER=1 ONECAD_REQUIRE_GPU=1`, an explicit freshly staged
`ONECAD_WORKER_PATH`, and `cargo test -p onecad-ui --lib typed_real_worker_import_export -- --include-ignored`.
The macOS test uses Metal for the host's bounded preparation budget and
`/usr/bin/unzip` to verify 3MF archive integrity. This service qualification does
not establish native dialog, physical input, or production continuity acceptance.

Recovery decisions and semantic restoration have deterministic service tests; the
physical crash/restart, autosave, second-crash and clean-close drill remains a
required native acceptance gate.

Only implemented controls are exposed. Select a worker-produced profile fill in
the viewport, choose Extrude, enter a length or expression, wait for its real
preview and choose Create. New Body is the default. Add and Cut require an explicit
visible, healthy target body from the feature card or body tree; choosing a target
retains the exact profile region and its holes. Mode and target changes invalidate
the prior preview. Flip negates the same signed distance expression through the
application resolver. Select an editable history row and an applicable numeric field to edit its stored
parameters. Existing-feature edits rebuild on Apply: PreviewOp appends a candidate
at HEAD and cannot correctly preview replacement of an existing operation.
Choose Sketch, then XY, XZ, YZ or Selected planar face. The face option requires
a checked viewport face selection. One click selects an existing sketch row;
double-click or Properties Edit enters it. Camera, picking and rendering use the
same effective sketch frame, preserving the persisted named-plane conventions.
Face entry queries OCCT's exact frame and projected boundary without holding the
document mutation lock. Runtime, revision, snapshot, worker epoch and provider
ownership are checked again before sketch and identity adoption. Dropping or
cancelling a candidate before admission changes no sketch, binding, history or
dirty state. Accepted work retains its owner through completion. Nonplanar or
unresolved support is refused; no world-plane fallback is substituted. Boundary
entities remain locked, and existing support regeneration/reopen rules apply.
Point, Line, Rectangle and Circle emit typed batches through the shared solver.
Rectangle exposes Corner and Center methods in the sketch inspector. Center
Rectangle retains its center through a construction diagonal and a solver midpoint
constraint; both helpers stay outside the material profile. Selection
keeps whole entities separate from endpoint, center and arc-point roles. Shift or
Command toggles ordered operands. A rightward marquee encloses; a leftward marquee
crosses. Ambiguous overlapping targets open an explicit chooser. Picking and
highlighting use the accepted captured view; stale targets cannot change selection.

The Constraints menu checks operands for Coincident, line Horizontal/Vertical,
Parallel, Perpendicular, Tangent, Concentric, Equal, Midpoint, Symmetric, OnCurve,
Fixed, point Horizontal/Vertical alignment and six dimension types. Distance
supports point-point, point-line and parallel line-line operands. Signed horizontal
and vertical distances and angles retain their signs. Angle fields use degrees;
the internal contract uses radians. Radius and Diameter require supported circular
curves. Incompatible operands show the refusal reason.

Dimension badges and inspector Edit open the existing constraint ID with its
referenced roles intact. Literal input removes an expression binding; expressions
bind or rebind through application resolution against current document variables.
Rejected constraint/dimension candidates preserve geometry and history. Badge
positions can be dragged, hidden and reset during the visit; this presentation
state is not document geometry or persisted placement.

Snap uses logical-pixel tolerances and a visible winning relation. Endpoint,
midpoint, center, origin, quadrant, analytic intersection, OnCurve and reference
guides persist supported constraints. Quadrants include both OnCurve and point
alignment. Polar and grid are placement guides; their labels do not claim a
persisted relation. Ellipse snapping currently exposes its center only. Inspector
options control snapping and optional 1 mm grid placement. Alt temporarily suppresses
optional snapping. Tab after an anchor opens numeric Line length, full Rectangle
width/height or Circle diameter. Point supports Tab before a pointer anchor and
accepts signed X/Y coordinates, including zero, from the sketch origin. Its numeric
batch includes an explicit fixed construction origin and signed distances. Tab moves
between fields, Enter creates one constrained batch and Escape cancels the draft;
blur never commits. Application authority resolves authored expressions. Line
continuation reanchors to the accepted solved endpoint.

Arc offers center/start/end and start/end/through methods; Slot places two
centerline endpoints followed by full width. Tab after two anchors opens Arc
Radius and signed Sweep, three-point Arc Radius, or Slot full Width. The signed
center-arc sweep controls geometry only; Radius and Slot Diameter persist as
driving constraints. Numeric three-point radius retains both placed endpoints,
the selected center side and minor/major branch. Values below half the chord,
nonpositive/nonfinite radii and degenerate candidates refuse without a document
edit. Numeric expressions bind through application-owned constraint admission.

An armed Line chain with a known solved outgoing tangent supports the Tangent
arc checkbox or plain A. Shift+A activates three-point Arc. Primary drag beyond
4 logical pixels on either axis promotes the eligible chain to tangent Arc;
an ordinary click remains Line. Release recomputes snapping and submits one
batch; Escape, capture/focus loss, stale context or release over interactive UI
cancels. A unique existing Line/Arc endpoint can seed continuation; ambiguous
junctions never choose a preceding curve. Arc endpoints retain entity plus
Start/End role without synthetic endpoint points. Tangent Arc numeric input
exposes one Radius field, preserves the pointer bend side and sweep, and authors
Radius together with the structural weld and TangentAtPoint. Every accepted
primitive reanchors from solved geometry and has one local Undo entry.

Select supports solver-backed point/line-endpoint, line-body, circle/arc radius
and arc endpoint/center gestures; ellipse interaction is center-only. The host
paints checked transient previews and commits one accepted drag edit. Escape or
capture/focus loss cancels the gesture. See the [native gesture contract](../../docs/design/native-sketch-gestures.md)
for fencing, bounded cleanup, no-op history and validation boundaries.

Construction mode marks new primitives, and selected whole entities can toggle
construction. Construction participates in solving but not material profiles.
Entity/constraint deletion uses the application repair admission path; locked
projections remain protected. Unhealthy sketches can remove constraints and repair
without passing the healthy-candidate creation gate. Missing, cached or invalid
solver truth never displays as fully constrained; missing point reporting remains
neutral instead of inheriting a whole-curve DOF claim.

Finish sketch keeps accepted edits; Discard sketch edits uses guarded whole-visit
application history. Enter first clears a transient draft; a later Enter finishes.
Escape unwinds numeric input, gesture/draft, tool, then selection. Idle Escape
stays in the sketch. Read-only refresh never opens another edit session.
Sketch and History rows select on one click and expose Properties. Double-click
and the Properties Edit action use the same sketch or saved-feature entry path,
including initially unselected rows. Selection records the owning primary press's
coordinates and Shift/Command mode, retaining that mode through marquee and
overlap choices. Ambiguous multiple primary cycles in one frame are refused.
Automated host evidence and physical workflow acceptance are separate; see the
[recurring host gate](../../docs/native-host-ci-gate.md).
Focused text owns undo/redo and clipboard actions. Outside text editing, the title
bar, File menu, native Edit menu and keyboard share the same history dispatcher.
An active sketch uses application-owned, session-scoped history; model history is
used outside sketch mode. Undo or Redo first clears a transient sketch draft without
changing the document. Another invocation moves one committed same-sketch step.
History cannot cross the entry boundary, replay a foreign redo, or survive an edit
visit, runtime, head, revision or worker-epoch change. A detached candidate is solved
before the history move commits; errors and rejected solves preserve both stacks and
authoritative geometry. Empty history is explicit. Finish/discard retains the existing
session grouping and clears redo owned by the closed visit. Refreshing an existing
sketch timeline record belongs to the same model Undo step as the finished net
sketch edit: one Undo restores both the live sketch and its regeneration record.
An edit-free Finish adds no history. Initial sketch-record creation retains its
existing history contract. No UI snapshot stack is created. Evicting older model
transactions shifts the visit boundary; the newest
200 retained sketch edits remain undoable. If a visit's own edits have been
evicted, Discard conservatively keeps the changes and reports that history was
trimmed; Finish keeps the retained granular history instead of a net undo step.
Japanese IME and native menu/dialog behavior remain unverified. Further modeling creation tools and full interaction parity
are not implemented in this host.

Camera input consumes ordered native events instead of smoothed scroll totals.
Mouse wheels zoom, two-finger scroll pans, Shift plus two-finger scroll orbits,
and pinch zooms at the cursor on the camera-facing target plane. Shift stays
latched through the current trackpad gesture and its recent momentum phase.
Explicit native source identity distinguishes a smooth mouse wheel from a
trackpad; unknown point input needs a phased gesture to take the trackpad path.
RMB and MMB drag pan; Shift+RMB drag orbits. Primary-button ownership and open
popups block camera motion while input state still advances. Native device
preference persistence and physical mouse/trackpad qualification remain open.

Durable commands reserve one of eight permits before entering the service
runtime and execute in FIFO order through regeneration. Accepted authoring and
geometry completion are separate results. A failed fresh provisional operation
uses only its backend-issued guarded rollback receipt; edits, NeedsRepair and
unknown completions are retained. Preview drafts coalesce to one pending request
and one worker request in flight. Cancellation invalidates completion delivery;
it does not claim to interrupt an executing worker operation. Late results must
match document, runtime, revision, worker head and gesture identity.

Service completion, close-request interception and settings persistence run in
`App::logic`, including when the window is hidden or occluded and eframe does not
call `App::ui`. A dirty close cancels the native close and makes the confirmation
visible; clean shutdown waits for the service actor's stopped message. The ignored
`app_logic_tests::occluded_app_logic_delivers_new_and_protects_close_without_ui`
regression drives the real host through logic-only ticks with a production worker
and Metal. It checks document replacement delivery, dirty-close protection and
shutdown progression without presentation; it does not establish physical input
or clean AppKit teardown acceptance.

Raw-input routing must process only fresh events. Eframe can prepend events that
egui has not consumed between logic-only ticks. `input::RoutingState` tracks this
retained prefix against the cumulative egui pass number, routes newly appended
events once, and restores retained text/IME input for the next presentation pass.
Do not route the retained prefix again: a text Undo or native-menu injection could
otherwise become a model Undo after focus changes. The `input::tests` regressions
cover retained text Undo, fresh Redo, native-menu injection, egui-pass advancement,
IME commit and early-return preservation.

Select a body and choose Move / Rotate to use the SolidCraft-derived transform
gizmo. Axis stems, plane squares and the center move the draft; rotation rings
rotate it with 5-degree snapping unless Alt, Control or Command is held. A drag
updates the preview; Create commits one typed TransformBody operation. Cancel
discards the provisional operation. The navigation cube exposes face/corner
views, orbit, quarter turns, roll, home, fit and projection switching.

Display exposes supersampling and section
planes. Section clipping is view-only: topology selection is disabled while a
section is active, and section changes are disabled during authoring. CPU picking
does not invent selectable section geometry.

The primary viewport uses OneCAD's indexed quality `Renderer`. Its checked OCCT
geometry, AO, studio lighting, contact shadows, grid and silhouette pipeline are
application-owned. Native and headless captures use this same renderer; competing
application and prototype renderers are retired. Native assets live in
`assets/native`, and checked capture fixtures in `fixtures/render`.
Committed geometry requests fine tessellation. The renderer owns four display
styles: Wireframe, Shaded, ShadedEdges (the default), and Xray. The Display popover
exposes these modes through the existing pending-options and GPU fence path.
Xray is disabled with a capability reason when the shared device lacks
`FLOAT32_BLENDABLE`; renderer validation remains strict.
Wireframe excludes surface fills and shadows;
Xray uses weighted blended transparency without AO or contact shadows.
The host supplies eframe's shared wgpu device/queue to the CAD renderer and
samples its output texture through egui, without CPU image readback. CPU mesh
checking and preparation run on the service runtime. Resource replacement waits
for both CAD completion and the previous frame's final egui sampling submission.
CPU picking remains synchronous against the last drawable camera and scene;
pending navigation does not change hover, click, profile or gizmo captures.
An unchanged redraw retains the capture identity so marquee and snap hysteresis
survive repaint. Scene, camera, viewport, display options (including Wireframe),
theme or preview changes create a new capture and invalidate pending picks.
Topology highlight preparation runs off the UI thread, with one active job and
one bounded delivery. Selection sequence and scene identity reject stale results.
The host and headless renderer tests negotiate the same optional float-stencil
capability, with a 24-bit stencil fallback.
Section contours are prepared off-thread by one latest-only bounded worker. Scene,
preview and plane keys reject stale results; source scene reservations remain
alive while canceled jobs finish. Section changes publish options and contours
together after GPU and sampling fences drain. Rejected changes retain the prior
drawable frame. Synthetic contours and caps carry no selectable topology IDs.
Committed and preview contour preparation execute sequentially. Each retained or
executing request reserves an additional 64 MiB within the shared 768 MiB host
cap; preview scratch is limited by retained committed contour storage.
The host polls device completion even while the previous egui sampling fence is
pending; otherwise the callbacks needed to release that fence cannot advance.
Render watchdog acknowledgements bind the captured document, runtime, revision,
snapshot and body IDs. They are sent once after committed GPU work completes,
never for a preview or failed submission; they do not certify OS presentation.

Viewport errors disable stale viewport actions without invalidating the document
or geometry worker. Device loss enters a controlled unavailable state and requests
the existing recovery autosave flush; save and sketch finish/discard remain
available. Surface recovery belongs to eframe. Automatic device replacement is
outside this milestone. Resize publishes a new egui texture registration only
after renderer allocation succeeds and final sampling drains; zero-sized views
release targets only after those same fences drain.

Conservative CPU handoff reservations cover retained current/pending/building
scenes and preview payloads, capped at 768 MiB. Per capture, source meshes are
capped at 32 MiB, prepared CPU payload at 64 MiB, and aggregate profile
source/decoded/scratch estimates at 16 MiB. Retained authored records, including
extension fields, have a conservative 16 MiB aggregate estimate with streamed
size/depth checks; no document-sized JSON buffer is built. Each sketch snapshot
and solver DTO has a 1 MiB streamed serialized-size cap. There are at most 256 bodies, 128
sketches and 512 feature rows. These limits do not establish a total process RAM
bound: application state, incoming DTO/record and protocol reply allocation before host validation,
GPU-driver storage and toolkit resources have separate lifetimes and limits.
Oversized or malformed payloads fail closed and disable stale picking/commit.

## Editor chrome

The window follows the OneCAD Final design (`docs/design/native-ui/final/`). The
presentation components live in the `onecad-widgets` crate (design tokens, baked
icons, fonts and egui widgets, no OneCAD dependencies); this crate only composes them
with application data. Chrome modules:

- `layout.rs`: pure geometry of the floating chrome (title bar, Explorer,
  Inspector, tool pill, feature card, view cluster, nav pill) with unit tests.
- `shell.rs`: orchestrates the bars, panels and overlays each frame.
- `explorer.rs`: Bodies / Sketches / Datums tree, workspace menu; the sketch being
  edited lists child rows (line, circle, arc and constraint counts) from the live
  session.
- `inspector.rs`, `inspector_props.rs`, `inspector_history.rs`: Properties (title
  block and rows from existing projection data; unavailable values show a dash) and
  History (feature rows, rollback marker, info box).
- `pill.rs`, `tool_registry.rs`: selection-dependent tool pill. Tools without a
  backing action are disabled with the reason "Not available yet".
- `feature_card.rs`: card for the running model tool (numeric field, Create / Apply,
  Cancel). Enter confirms and Escape cancels under the same predicates as before.
  Preview refusal/failure appears inline.
- `session_strip.rs`, `constraints_menu.rs`, `constraint_authoring.rs`: sketch
  session strip, applicability-driven constraint menu and scoped dimension editor.
  Unsupported constraints remain disabled.
- `start_screen.rs`: Home screen opened from the title bar, with New part and
  Open or import actions and real QA-profile recents. Assembly creation remains
  unavailable. "Back to document" or Escape returns to the editor.
- `overlays.rs`, `display_menu.rs`, `bars.rs`: nav pill, view cluster, Display menu,
  title bar and floating controls; the editor has no bottom status bar.
- `appearance.rs`: applies View > Appearance.

Cmd+1 toggles the Explorer and Cmd+2 the Inspector (ignored while a text field has
focus). View > Appearance in the native menu offers Light, Dark and System; Dark is
the default and System follows the OS theme, re-evaluated every frame.

Appearance, panel visibility, Inspector tab and recent-card layout persist in
`config/native-settings.json` inside the locked QA profile. These preferences load
before the first presentation; System resolves against the current OS theme.
Transient filters, menus, commands and document state are excluded. Writes run
only after a preference changes, on one background writer using atomic durable
replacement; shutdown drains the final change before releasing the profile lock.
Corrupt, oversized, linked or unsupported-version settings remain untouched and
disable preference writes for that session, with a startup warning. This format
does not migrate production preferences or establish production data continuity.

```sh

```

## Native input diagnostics

Set `ONECAD_INPUT_TRACE=1` before launch to enable bounded input evidence in the
existing `ONECAD_LOG_DIR/dev.jsonl` logger. The default is disabled. Keep the
isolated QA profile and its log directory for each run. Filter JSONL records by
`target == "onecad_input"`; their message is `native.input_trace`. The `context`
and `detail` fields contain JSON strings that can be decoded separately.

Each record carries a process-local increasing `sequence` and monotonic
`elapsed_us` since trace initialization. The trace writes at most 16,384 normal
records plus one `trace.limit` record per host launch. It records at most 64
ordered events per fresh input batch, with an explicit omitted count; detail
payloads are limited to 2,048 bytes and identity strings to 128 UTF-8 bytes.
These caps apply to this diagnostic stream, not to other application logs.
Text, clipboard, IME, image and accessibility payload contents are omitted.
Ordinary typing keys are redacted; control and command shortcut keys remain
visible. Text events report byte counts only.

The evidence includes fresh input before dispatch, batch focus and scale,
logical pointer coordinates, native menu routing and text focus, accepted
capture document/runtime/revision/scene/view identities, sketch phases,
pointer ownership snapshots, dispatched actions, bounded refusals, service
completion/delivery/wakes, actual repaint requests and UI/logic pass numbers.
Repaint observation preserves eframe's integration callback and does not add
continuous redraw or change click timing. An `unclaimed` pointer snapshot means
that no tracked host owner is currently captured; event-specific overlay and
focus fields still determine whether a new gesture is allowed.

`viewport.gpu_submit` and `viewport.gpu_complete` identify submitted and completed
CAD render work. `viewport.image_queued` means the captured image was added to an
egui UI pass. Neither event proves that macOS physically presented that frame.
Asynchronous records retain explicit result identities in `detail`; their
`context` is the most recently observed host state. Its `scene` identifies the
accepted display; `view_scene` identifies the captured image and can differ while
new geometry waits for rendering. Use screenshots and document
inspection to establish visible and persisted results.

The ordinary Select-tool drag regression covers press/move/release in one UI
frame, press and move together with release in the next frame, and separate
frames. Raw event sampling preserves the original press and exact release,
ignores motion outside those boundaries, and refuses multiple primary press
cycles in one batch before starting a drag. Focus loss, PointerGone, Escape,
overlays, release over chrome followed by a return to the viewport, stale
captures and service-driven completion without more pointer input have dedicated
checks. This is synthetic host qualification, not physical
input or full modeling workflow acceptance:

```sh
ONECAD_REQUIRE_WORKER=1 ONECAD_REQUIRE_GPU=1 \
ONECAD_WORKER_PATH="$PWD/worker/build-native/onecad-worker" \
  cargo test -p onecad-ui app_logic_tests::gesture_delivery_tests \
  -- --ignored --test-threads=1
cargo test -p onecad-ui input_trace
```

New profiles default to Light appearance; saved appearance choices take precedence.

Inspector use 32 px toggles both inside their headers and when collapsed. The
collapsed Inspector toggle sits below the viewport controls, centered in their
column. The
navigation cube occupies 104 px. Saved feature parameters expand inline beneath
their History row, with the same expression validation, Apply and Cancel actions.
New feature creation retains its floating parameter card. Application diagnostics
remain recorded without an Activity overlay.

The Display popover uses a compact 280 px width, render-style icons and an active
row highlight/checkmark. Projection fills the popover width. X-ray, SSAA and
Section are grouped under More settings. Hidden line remains disabled until the
renderer supports it.

The sketch Finish/Discard strip centers beneath the main toolbar, clamped to its
free layout lane. Long sketch labels retain horizontal scrolling and reachable
actions.
