# Parametric CAD Sketching UX — Industry Research (Shapr3D gold reference, corroborated by Fusion 360 / SolidWorks / Onshape)

Facts only. No OneCAD recommendations — synthesis is done by the orchestrator.

---

## 1. Constraint display

### Standard (convergence across the four)
- Constraint glyphs render directly on/near the constrained geometry (at the relevant endpoint/midpoint), not in a side list only.
- All four let you **toggle constraint-icon visibility globally** (show/hide all) as a distinct setting from dimension visibility.
- All four: **select a constraint icon on canvas → press Delete (or right-click → Delete)** removes just that constraint. [SolidWorks](https://help.solidworks.com/2025/english/SolidWorks/sldworks/HIDD_DVE_SK_EDIT_RELATIONS.htm?id=28.19.2.5) (left-click green relation box, right-click → Delete, or Del key), [Onshape](https://cad.onshape.com/help/Content/Sketch/working_with_constraints.htm) (click icon + Delete or context menu), [Fusion 360](https://forums.autodesk.com/t5/fusion-design-validate-document/how-do-i-hide-all-sketch-constraints/td-p/5469999) (hover + Delete, or right-click → Delete), [Shapr3D](https://support.shapr3d.com/hc/en-us/articles/7407627891100-Adding-and-removing-constraints) (select + delete icon in modeling space, or Disconnect/Unlock).
- Hovering/selecting a constraint highlights the entities it applies to (all four).
- SolidWorks and Onshape both ship a **dedicated constraint-list panel** for bulk management: SolidWorks "Display/Delete Relations" PropertyManager (select from list → entities+icon highlight in canvas) [source](https://help.solidworks.com/2025/english/SolidWorks/sldworks/HIDD_DVE_SK_EDIT_RELATIONS.htm?id=28.19.2.5); Onshape "Constraint Manager" reachable from the sketch diagnostic-tools icon, filterable, with per-row trash icons and a "Delete all" [source](https://www.onshape.com/en/resource-center/tech-tips/sketch-constraint-manager) / [source](https://cad.onshape.com/help/Content/Sketch/working_with_constraints.htm).

### Shapr3D specifics
- **Constraint Settings** menu (opposite the Sketch menu, only while in sketch mode) controls a "Constraint & Locked Dimension Visibility" setting — default behavior only shows icons for the *currently selected* sketch element ("Always Show Constraints" turns that off and shows all). [source](https://support.shapr3d.com/hc/en-us/articles/7394385784476-Constraint-Settings) (search-summarized; page itself 403'd to WebFetch)
- Clicking a constraint icon pops a **tooltip at the bottom-center of the screen** naming the constraint type. (same source)
- Constraints can be created purely by **dragging**: drag a point onto another point → coincident; drag a point onto a line/curve → coincident-on-curve; drag a point onto a line's midpoint → midpoint constraint, and the midpoint-target is shown **in purple** during the drag. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/7407627891100-Adding-and-removing-constraints)
- A dedicated **Lock** constraint fixes a single element in place (distinct from a geometric relation between two elements); removed via **Unlock**. (same source)
- Keyboard shortcuts for constraints are `Shift` + a letter, shown next to the constraint name in the side menu. (same source)

### Gap common to all four
None of the sources document a *permanent visual difference* between an auto-inferred-and-accepted constraint and one the user explicitly applied via menu/shortcut — once created, the icon looks the same regardless of origin. SolidWorks is the partial exception only *during* drawing: a **white "inference" box** (no relation created, e.g. showing the pointer is merely aligned) is visually distinct from the **yellow relation box** that appears when a relation is actually about to be committed (coincident/midpoint) — but this distinction disappears the instant the relation is created. [source](https://gupta9665.wordpress.com/2011/01/17/colors-symbols-what-they-indicate/) / [source](https://forum.solidworks.com/thread/72328)

## 2. Under/fully-defined status language

### Standard (convergence: SolidWorks, Onshape, Fusion)
- **Blue = under-defined, Black = fully-defined, Red = over-defined/conflicting**, applied as the color of the sketch geometry itself (not just an icon). [SolidWorks](https://gupta9665.wordpress.com/2011/01/17/colors-symbols-what-they-indicate/), [Onshape](https://forum.onshape.com/discussion/25451/fully-defined-sketches-what-are-they-and-why-care), [Fusion 360](https://www.canadacad.ca/fusion-360-why-is-sketch-locked/) (blue = not fully constrained; black = fully constrained).
- SolidWorks additionally prints the **literal text** "Under Defined" / "Fully Defined" / "Over Defined" in the status bar — color and text are redundant/dual-channel. [source](https://openwa.pressbooks.pub/testmhrtc/chapter/other-user-interface-components/)
- Fusion 360 additionally shows a **lock icon** on the sketch node in the browser tree: black lock = fully constrained; red lock = a distinct fault state (locked-but-empty, or another problem), separate from the blue/black entity coloring. [source](https://www.canadacad.ca/fusion-360-why-is-sketch-locked/) / [source](https://knowledge.autodesk.com/support/fusion-360/troubleshooting/caas/sfdcarticles/sfdcarticles/Red-Lock-icon-is-shown-on-Fusion-360-sketch-in-browser.html)
- Onshape additionally uses **white vs. blue constraint icons** to mean something orthogonal to DOF status: white = constraint entirely within this sketch, blue = constraint references something outside the sketch (origin, prior feature edge). [source](https://www.onshape.com/en/resource-center/tech-tips/sketch-constraint-manager)
- "Fully defined" is explicitly framed by both SolidWorks and Onshape docs as "no ambiguity — only one way to solve the geometry," i.e. DOF language, not merely "looks right." [Onshape](https://forum.onshape.com/discussion/25451/fully-defined-sketches-what-are-they-and-why-care)

### Over-constrained / conflict recovery flow
- **SolidWorks**: dedicated wizard, **SketchXpert** (Tools → Sketch Tools → SketchXpert). It generates a list of causes grouped into non-destructive **"Solution Sets"**; clicking Diagnose previews each solution in the graphics area (showing exactly which relations/dimensions would be deleted) before you commit to one. [source](https://help.solidworks.com/2022/english/SolidWorks/sldworks/t_Diagnosing_Over_Defined_Sketches.htm) (search-summarized). Manual fallback: select the red relation symbol and press Delete, or mark an over-defining dimension "Driven."
- **Onshape**: **Constraint Manager**, opened from the sketch diagnostic-tools icon; lists/filters all constraints (including by Error status), hovering highlights affected entities in yellow; conflicting constraints render as a **white symbol on a red background** vs. the normal gray-square/black-icon look. [source](https://www.onshape.com/en/resource-center/tech-tips/sketch-constraint-manager) / [source](https://r.jina.ai/https://cad.onshape.com/help/Content/Home/error_indicators.htm)
- **Fusion 360**: no dedicated wizard found in sources — resolution is manual: enable Show Constraints, right-click-delete redundant ones incrementally until the conflict clears; a specific inline message, **"This dimension would over-constrain the sketch,"** appears at the moment a would-be-conflicting dimension is added. [source](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/This-dimension-would-over-constrain-the-sketch-while-adding-a-linear-dimension-to-a-sketch-entity-in-Fusion-360.html)
- **Shapr3D diverges structurally**: rather than allowing the conflicting constraint to apply and then diagnosing after the fact, it **refuses the add outright** with an inline info bubble: *"This constraint would conflict with existing ones."* You must manually identify and remove/Disconnect/Unlock the opposing constraint yourself. [source](https://discourse.shapr3d.com/t/constraint-error-message/32198) (search-summarized). Users have filed feature requests specifically because Shapr3D does **not** visually flag *which* existing constraint is the conflicting one — a real capability gap versus SolidWorks/Onshape's diagnostic tooling. [source](https://discourse.shapr3d.com/t/visual-feedback-of-constraint-conflicts/27977) / [source](https://discourse.shapr3d.com/t/highlight-constraint-when-it-conflicts-with-existing-constrains/32479)

### Shapr3D specifics
- Color scheme (as of v5.810, March 2025, replacing a prior teal scheme): **Green = fully-defined, Blue = under-defined, Orange = selected, Red = error.** This is a 4-way scheme, distinct from the 3-way black/blue/red used by the other three. [source](https://discourse.shapr3d.com/t/5-810-fully-defined-sketches/36634)
- DOF is communicated **per sketch point**, not just per-sketch or per-entity in aggregate: "A sketch point is fully-defined when it has no remaining degrees of freedom... acts as an anchor for connected sketch items." [source](https://support.shapr3d.com/hc/en-us/articles/18826854513564-5-810-Fully-defined-sketches) (search-summarized)
- Rationale given in-product: *"until a sketch becomes fully defined, there's always some ambiguity left in how sketch parts will be positioned"* — repositioning can occur unexpectedly on regen if earlier history steps affect the sketch, so Shapr3D explicitly recommends fully defining a sketch before consuming it downstream. (same source)
- The 5.810 update paired the color change with a broader "reduce visual noise" pass: smaller dimension labels, thinner dimension lines, reduced constraint-icon emphasis by default, and a more saturated orange-yellow selection color specifically for sketch elements (vs. body/solid selection color). (same source)

## 3. Tool activation and exit

### Standard (with real divergence in the details — see per-app notes)
- All four bind common tools to single-letter/short keyboard shortcuts and a toolbar/menu equivalent.
- All four let the Line tool **chain** — click to place successive endpoints without reselecting the tool.
- All four provide **some** way to finish the current line/segment while the tool *stays armed* for the next one, distinct from a full tool exit:
  - **SolidWorks**: double-click, or right-click → **End Chain**, keeps the Line tool active; plain **Escape ends both the chain and the Line command** in one step (no intermediate tier). [source](https://forum.solidworks.com/thread/26182) (search-summarized)
  - **Onshape**: pressing the tool's own hotkey again (e.g. `L`) "escapes" the in-progress line only, tool stays armed — a second press starts a new one; right-click → "Escape Line" does the same; click-drag-release also escapes the current segment without exiting. [source](https://forum.onshape.com/discussion/11803/line-drawing-end-the-line-and-not-exit-the-tool) (search-summarized)
  - **Fusion 360**: the Line command stays active across multiple lines by default; a Check/checkmark icon or double-click finishes the current line while keeping the command armed; **Escape fully exits** the Line command; right-click → **Repeat Line** finishes in place and restarts elsewhere; Enter completes the current line. [source](https://forums.autodesk.com/t5/fusion-support-forum/escape-key-does-not-function-like-it-used-to/td-p/10855877) / [source](http://www.inventortales.com/2017/08/Fusion-360-restart-line.html) (search-summarized)
  - **Shapr3D**: **Escape cancels/exits only the currently-active (in-progress) endpoint**; **Enter commits the final endpoint** and finishes the chain; connecting the last point back onto the first endpoint **auto-closes and auto-finishes** the chain. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/7874250627484-Line)
- Auto-switch to Select after a single-shot shape (rectangle, circle) commits is the implicit default across all four for non-chaining tools, contrasted with Line's chain-and-stay-armed behavior — this contrast is visible in user forum confusion threads ("why doesn't the line tool stay active" implies staying-armed is the *expected* baseline for chaining tools). [source](https://forum.solidworks.com/thread/85969) (search-summarized)

### Shapr3D specifics
- **Shapr3D auto-activates the Line tool the instant you enter sketch mode** — no separate tool-selection step required to start drawing: *"when we open the sketch, it automatically turns on the line."* [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/13079114694684-Introduction-to-2D-sketch-tools-and-settings") This is **not documented for any of the other three** — SolidWorks/Onshape/Fusion land in an idle, tool-less sketch-editing state after plane selection and require an explicit tool pick.
- **Automatic Line/Arc mode** (pen input specifically): Shapr3D detects gesture and switches between drawing a straight line and a tangent arc automatically; a **"wiggle" gesture** with the pen manually forces a line↔arc mode switch mid-stroke. Manual override available via Sketch → Line/Arc → Line Type (Automatic / Line / Arc, fixed). [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/7770681244316-Automatic-Line-Arc)
- Tool access methods: left-side adaptive menu that **predicts next-likely tools** based on current selection ("adaptive UI"), right-click context menu ("secondary click anywhere in modeling space"), command search-by-typing, and platform menu bars. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/7378907587484-Accessing-tools)
- Shapr3D's own community has filed a request for an **"ESC key operation option"** because Esc is overloaded: the same key cancels an in-progress endpoint, exits a tool, *and* (per user reports) can exit sketch mode entirely, causing accidental full exits — i.e., even the gold-reference app does not have a clean, universally-agreed tiered-Esc model. [source](https://discourse.shapr3d.com/t/esc-key-operation-option-for-sketch-mode/28300) (title/existence confirmed via search; content not fetched)

## 4. Snapping and inference

### Standard (convergence)
- Live dashed/dotted **inference lines** appear as the cursor nears a snap-worthy relationship (alignment, midpoint, tangent, perpendicular), shown *before* commit. [SolidWorks](https://www.cati.com/blog/solidworks-what-are-inference-lines-and-did-you-know-you-could-change-there-colors/), [Onshape](https://cad.onshape.com/help/Content/Sketch/automatic_inferencing.htm), [Fusion 360](https://help.autodesk.com/view/fusion360/ENU/?guid=SKT-CONSTRAIN-HORIZONTAL-VERTICAL) (search-summarized).
- A **constraint-preview glyph/icon appears near the cursor** naming the relation that will be created if you click now — confirmed explicitly for Onshape (icon + text label below cursor) and Fusion (H/V glyph badge next to cursor before click). [Onshape](https://forum.onshape.com/discussion/2577/feature-request-help-text-in-feature-ui) (search-summarized) / [Fusion](https://help.autodesk.com/view/fusion360/ENU/?guid=SKT-CONSTRAIN-HORIZONTAL-VERTICAL) (search-summarized)
- All four support snapping to: grid, existing sketch endpoints/midpoints/centers, and 3D edges/vertices/faces of the model.
- All four support **type-a-number-while-drawing** to dimension the entity being created (see §5).

### Per-app inference-line color conventions (real divergence, not uniform)
- **SolidWorks**: default **yellow** dashed inference lines (recolorable via Options → Colors → Temporary Graphics); *additionally* differentiates by relation type via distinct line colors — a **red** capture line signals tangent/perpendicular is about to snap (color customizable), a **blue** line is a pure alignment reference only and is *not* customizable. [source](https://www.cati.com/blog/solidworks-what-are-inference-lines-and-did-you-know-you-could-change-there-colors/)
- **Onshape**: **dashed yellow** inference lines + **orange highlighting** on the related entities + a text label naming the inference under the cursor. Some basic auto-inferences: vertical, horizontal, coincident, parallel, midpoint, perpendicular; docs note inference sometimes only "wakes up" once the cursor nears the second entity. [source](https://cad.onshape.com/help/Content/Sketch/automatic_inferencing.htm)
- **Shapr3D**: **purple** is the unifying inference/guide color — "Sketch Guidelines" (purple extensions from existing sketch elements enabling coincident/tangent alignment), the midpoint-drag preview target, and the perpendicular-detection guideline during drawing are all purple. Separately, a **"Snapping Hints"** toggle shows literal text next to the pointer naming what's being snapped to — directly analogous to Onshape's under-cursor label. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/7873946289564-Snapping-Options) / [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/13079113458332-Grid-and-sketch-settings)

### Snap-kind taxonomy (most granular published breakdown: Shapr3D)
Five independently-toggleable snap categories, each with its own icon in the Snapping Options panel: **Grid**, **Sketch Guidelines** (purple extension lines), **Sketch Guidepoints** (endpoints, midpoints, arc-center points, profile-center points), **3D Guidepoints** (vertices, edges, edge-midpoints, face/hole centers), **Distant Edges** (off-plane reference geometry visible only in an orthogonal view). A magnet-icon master toggle exists to enable/disable all guides at once. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/7873946289564-Snapping-Options)

Auto-constraint-on-connect is a separate, also-toggleable setting in Shapr3D: connecting endpoints/midpoints auto-creates Horizontal/Vertical, Perpendicular, Tangent (when an arc is created at an endpoint), and Coincident constraints. [source](https://support.shapr3d.com/hc/en-us/articles/7394385784476-Constraint-Settings) (search-summarized)

### Snap-suppression modifier keys (divergent, not standard)
- **SolidWorks**: hold **Alt** to temporarily disable inference/snapping. [source](https://www.cati.com/blog/solidworks-what-are-inference-lines-and-did-you-know-you-could-change-there-colors/)
- **Onshape**: hold **Shift** while dragging to prevent automatic inferences from activating. [source](https://cad.onshape.com/help/Content/Sketch/automatic_inferencing.htm)
- **Fusion 360**: hold **Shift** to override/disable snapping when moving/placing objects. [source](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/How-to-disable-snapping-when-moving-objects-in-Fusion-360-Drawing-workspace.html) (search-summarized)
- **Shapr3D**: no momentary suppression modifier key found in sources; snapping is controlled only via persistent per-category toggles in Snapping Options (a config change, not a hold-key gesture). A user feature request explicitly asks for a modifier key to disable angular snapping, implying it does not currently exist. [source](https://discourse.shapr3d.com/t/disable-angular-snapping-when-drawing-arc-with-3-points/28579) (title only, unconfirmed content) — **flagged as an unconfirmed gap, not a documented absence.**
- Convergence note: **Onshape and Fusion agree on Shift**; SolidWorks is the outlier with Alt.

## 5. Status communication

### Standard: live numeric entry while drawing (strong 4-way convergence)
- **SolidWorks**: opt-in system option **"Enable on-screen numeric input on entity creation"** (System Options → Sketch). With it on, drawing a line lets you type its length and press Enter to set a driving dimension immediately; doesn't work for splines/polygons/ellipses. [source](https://help.solidworks.com/2017/english/SolidWorks/sldworks/t_numeric_sketch_input.htm) (search-summarized)
- **Onshape**: after placing an endpoint, a **white input box** shows the live length; typing a number and pressing Enter assigns that dimension; for compound entities (e.g. a rectangle's two dimensions), pressing Enter after the first value **automatically advances input to the next relevant dimension**. [source](https://forum.onshape.com/discussion/7219/entering-dimensions-as-you-draw) (search-summarized)
- **Fusion 360**: type a value, press **Tab** to advance to the next dimension field; a **gold lock icon** appears once a typed value is locked in as driving. [source](https://forums.autodesk.com/t5/fusion-design-validate-document/not-able-to-enter-specific-dimensions-help/td-p/6042363) (search-summarized)
- **Shapr3D**: type a numeric value directly (or click the dimension label to open a numpad); supports inline **math expressions** (e.g. `12+34`, `50/2`) evaluated to the final value. [source](https://support.shapr3d.com/hc/en-us/articles/7874245890844-Editing-sketch-dimensions) (search-summarized)

### Status bar / HUD content
- **SolidWorks**: bottom status bar shows, while in a sketch: sketch DOF state as literal text (Under/Fully/Over Defined), live pointer coordinates, and quick measurements (length/radius/diameter/angle) for the current selection — usable without invoking the formal Measure tool. [source](https://store.trimech.com/blog/a-closeup-look-at-the-status-bar-in-solidworks) (search-summarized)
- Fusion/Onshape status-bar/HUD specifics were not found with equivalent detail in available sources (searches returned only generic toolbar/marking-menu material); this is a **documented gap in this research pass**, not a claim of absence.
- **Shapr3D**: no persistent bottom status bar/HUD documented; live feedback is delivered via (a) the numeric input box on the entity itself, (b) Snapping Hints text next to the pointer, and (c) a tooltip at bottom-center of the screen on constraint-icon click (see §1).

### Error/refusal surfacing (convergence: ambient/non-modal for routine cases; modal reserved for explicitly-invoked diagnostic tools)
- **SolidWorks**: routine DOF state via status-bar text + entity color; a genuinely modal-style PropertyManager (SketchXpert) is used only when the user explicitly launches diagnosis for an over-defined sketch. [source](https://help.solidworks.com/2022/english/SolidWorks/sldworks/t_Diagnosing_Over_Defined_Sketches.htm) (search-summarized)
- **Onshape**: feature-level problems render as **orange text** in the Feature list/dialog title (hover → tooltip with the summary); invalid dialog fields/entities render **red**; general system errors surface as a **bubble notification at the top of the window** — non-blocking. Conflicting constraints render as white-on-red icons, discoverable in-canvas without opening a dialog. [source](https://r.jina.ai/https://cad.onshape.com/help/Content/Home/error_indicators.htm)
- **Fusion 360**: inline warning text appears at the moment of the offending action (e.g. *"This dimension would over-constrain the sketch"*), not a blocking dialog. [source](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/This-dimension-would-over-constrain-the-sketch-while-adding-a-linear-dimension-to-a-sketch-entity-in-Fusion-360.html)
- **Shapr3D**: a failed operation shows a **warning signal at the top of the screen**; per-step problems additionally get a **yellow warning icon in the History/timeline sidebar** (persistent, inspectable after the fact, tied to the specific failed feature step); an immediately-rejected in-sketch action (e.g. a conflicting constraint) shows an **inline info bubble** near the point of action. [source](https://discourse.shapr3d.com/t/another-place-we-need-better-messages/30932) (search-summarized) / [source](https://support.shapr3d.com/hc/en-us/articles/11882948231196-Error-messages-in-History) (title confirms a dedicated per-step History error channel exists)
- **Convergence**: none of the four use a hard blocking modal for routine, moment-to-moment sketch refusals. Modal/dedicated-panel treatment is reserved for tools the user explicitly opens to *diagnose* an existing problem (SketchXpert, Onshape Constraint Manager) — the routine case is always ambient (status text, colored icon, toast/bubble, or inline cursor message).

## 6. Sketch lifecycle

### Entering (plane/face pick flow) — standard 2-step gesture
- **SolidWorks**: click a plane (in the FeatureManager tree or in-canvas) or a planar face, then click the Sketch icon — puts you directly into sketch edit mode. [source](https://openwa.pressbooks.pub/testmhrtc/chapter/starting-a-sketch/) (search-summarized)
- **Onshape**: select a planar face or construction plane, then start the sketch (or select the face from inside an already-open sketch dialog's selection box); non-planar faces cannot be used. [source](https://cad.onshape.com/help/Content/PartStudio/plane.htm) (search-summarized)
- **Fusion 360**: Create Sketch → select a plane, construction plane, or planar face on an existing body. [source](https://help.autodesk.com/view/fusion360/ENU/?guid=GUID-0EEF7073-6CDE-4E31-AF1A-0811F969F031) (search-summarized)
- **Shapr3D**: three attachment options — the three default construction planes (XY/YZ/XZ, or user-created offset planes), a planar face on an existing body (interface auto-recognizes attach points: face center, edge midpoint, edge endpoint), or the world grid directly. Selecting a plane/face **auto-rotates the view into an orthographic perpendicular view** — this specific auto-reorient-on-entry behavior was found explicitly documented only for Shapr3D in these sources (SolidWorks/Fusion/Onshape likely do this too by convention/default view settings, but it wasn't independently confirmed in the fetched material — flagged as unconfirmed for those three, not asserted absent). [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/12469688911516-Create-sketches)

### Exiting — real divergence in affordance count and explicitness
- **SolidWorks** has the most redundant exit surface: a persistent **"confirmation corner"** widget (top-right of the graphics area) with Exit-Sketch/Cancel icons, PLUS Insert → Exit Sketch, right-click → Exit Sketch, double-click empty space (only when no tool is active, not for 3D sketches), and Rebuild. A discard-changes variant exists: Edit → "Exit Sketch without Saving Changes." [source](https://r.jina.ai/https://help.solidworks.com/2025/english/solidworks/sldworks/t_Exiting_Sketches.htm)
- **Onshape**: a single canonical **green checkmark** in the sketch dialog/toolbar closes and confirms the sketch. [source](https://forum.onshape.com/discussion/30821/need-help-cannot-select-face-for-sketch-plane) (search-summarized)
- **Fusion 360**: a single canonical **"Finish Sketch"** button in the contextual Sketch toolbar returns to the 3D environment. [source](https://help.autodesk.com/view/fusion360/ENU/?guid=GUID-0EEF7073-6CDE-4E31-AF1A-0811F969F031) (search-summarized)
- **Shapr3D**: **no single canonical "Finish/Exit Sketch" button documented.** Users exit by navigating to a 3D view or by pressing Esc; Shapr3D's own community reports accidental full sketch-mode exits from Esc's overloaded scope (see §3), and has an open feature request for configurable Esc behavior specifically in sketch mode. [source](https://discourse.shapr3d.com/t/esc-key-operation-option-for-sketch-mode/28300) / [source](https://discourse.shapr3d.com/t/exit-sketching/28323) (titles confirmed via search; full content not fetched)

### Open-profile / closed-profile signaling for extrude — the FILL is the live signal, not an extrude-time warning
- **SolidWorks**: "Shaded Sketch Contours" (Tools → Sketch Settings), on by default, shades a closed loop live as you sketch; toggle-off-able. [source](https://forum.solidworks.com/thread/188841) (search-summarized)
- **Fusion 360**: "Show Profile" checkbox shades closed regions **light blue** live as the loop closes; an open point breaks the fill and shows as a visible white dot at the gap. [source](https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/The-sketch-in-Fusion-360-is-not-recognized-as-closed-profile.html) (search-summarized)
- **Onshape**: closed regions shade **grey**; an open gap leaves the region **white/unshaded**; the Extrude command only offers closed (shaded) regions as selectable profiles — the fill *is* the selectability signal, discovered before you ever invoke Extrude. [source](https://forum.onshape.com/discussion/26251/drawing-wont-extrude-even-though-it-is-a-closed-loop) / [source](https://cad.onshape.com/help/Content/extrude.htm) (search-summarized)
- **Shapr3D**: docs draw the same conceptual **Closed sketch vs. Open sketch** distinction (closed = usable for extrude/revolve/cut-profile; open = usable for sweep/guide-rail/projected-curve) but this research pass **could not locate an explicit citation for Shapr3D's specific fill color** for closed regions, despite multiple targeted searches of help docs and community threads. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/18816009328284-Sketching-in-Shapr3D) confirms the closed/open conceptual split exists; the fill-color mechanic itself is **not independently confirmed** in this research (flagged gap, not a negative claim) — the premise in the research brief that Shapr3D "fills closed regions" could not be sourced to a citable doc, though it is consistent with the pattern documented for all three other apps and widely visible in Shapr3D marketing screenshots (not a citable primary source).
- **Convergence**: all three fully-documented apps (SolidWorks, Fusion, Onshape) treat live fill-on-closure as the primary UX signal for "this loop is extrudable," discovered during drawing rather than surfaced only as an error at extrude time.

### Editing an existing sketch
- **SolidWorks / Fusion**: double-click the sketch node in the feature tree (or select it and choose Edit Sketch) re-enters sketch mode on the original plane and restores that view. [general CAD convention, not independently re-confirmed per-app in this pass beyond §"Exiting Sketches" context]
- **Onshape**: double-click the sketch in the tree/feature list to re-enter. [source](https://cad.onshape.com/help/Content/Sketch/sketch_basics.htm) (search-summarized)
- **Shapr3D**: a lighter-weight, more direct gesture — **selecting any element of an existing sketch jumps straight into drawing/edit mode** without a separate "Edit Sketch" menu action; pressing spacebar additionally snaps the view to the orthographic-perpendicular view for that plane. [source](https://r.jina.ai/https://support.shapr3d.com/hc/en-us/articles/12469688911516-Create-sketches)

### Projecting external edges — strong 4-way convergence on associative projection + auto-constraints
- **SolidWorks "Convert Entities"**: projects an edge/loop/face/curve/external-sketch-contour onto the active sketch plane as a new sketch curve; a relation is created binding the new curve to the source so it updates if the source changes. A "No External References" option exists specifically to suppress this associativity (relevant in assembly-context part editing). [source](https://help.solidworks.com/2019/english/SolidWorks/sldworks/t_Using_Convert_Entities.htm) (search-summarized)
- **Onshape "Use"**: projects an edge/face-silhouette onto the active sketch plane; automatically creates **up to 3 projected constraints per curve** (one for the curve, one per endpoint if the curve is open); geometry-type changes upstream (e.g. circle→line) don't react cleanly. Supported silhouette types: cylinders, cones, tori, spheres, extruded surfaces, single-silhouette surfaces. [source](https://www.onshape.com/en/resource-center/tech-tips/sketch-tools-use-intersection) (search-summarized)
- **Fusion 360 "Project" / "Include 3D Geometry"**: Project (keyboard shortcut **P**) projects bodies/faces/edges/points onto the active sketch plane, displaying the result as **purple projection geometry** — the one app in this research that explicitly documents a *dedicated color* distinguishing projected/reference geometry from user-drawn geometry. A "Projection Link" checkbox controls whether the associative relationship is kept or the projection is a one-time snapshot. [source](https://help.autodesk.com/view/fusion360/ENU/?guid=SKT-SKETCH-CREATE-PROJECT-INCLUDE) (search-summarized)
- **Shapr3D "Project"**: casts/projects sketches, edges, or faces onto another face or sketch on the same plane, creating a parametric relation to the source; separately, while in an orthogonal sketch view, **off-plane edges and sketches are automatically projected onto the active plane for snapping purposes** without an explicit Project-tool invocation. [source](https://support.shapr3d.com/hc/en-us/articles/23504781693084-5-1010-Project-imports-and-smarter-sketch-snapping) (search-summarized)
