# iPadOS host architecture

Status: frozen contract for the iPadOS workstream (Plane ONECAD-270, IP01
ONECAD-448). Plane owns scope, status and evidence summaries; this file owns the
code-coupled boundaries. It does not assert any test result. See
[ADR-0018](../adr/0018-ipados-embedded-kernel.md) for the hosting decision.

## Scope and deployment

- Native UIKit application for **iPadOS 18.0 or later**. Device ARM64
  (`aarch64-apple-ios`, iPhoneOS SDK) and Apple-Silicon simulator ARM64
  (`aarch64-apple-ios-sim`, iPhoneSimulator SDK) are separate Mach-O platforms
  with separate build directories; they are never merged into one lipo slice.
- One `UIScene` with two or three open document tabs. Multiple independent
  windows and iPhone are separate scope.
- macOS keeps the production sidecar worker, its manifest checks and its
  existing presentation. Nothing in this workstream changes desktop defaults.

## Ownership

| Layer | Path | Owns |
|---|---|---|
| UIKit host | `platforms/ios/` | App/scene lifecycle, `CAMetalLayer` view, raw `UITouch`/Pencil capture and copying, `UIPencilInteraction`, hardware/software keyboard and text composition, `UIAccessibility` elements, document picker and file coordination, Xcode schemes and tests. Never owns CAD state. |
| Rust bridge | `crates/onecad-ios` | Versioned C ABI (`include/onecad_ios.h`), thread-affinity checks, panic containment, the egui frame loop without eframe, `wgpu` surface over the host layer, input normalization into the shared router, accessibility export, host-request queue. Static library (`staticlib`) for Xcode. |
| Shared editor | `crates/onecad-ui` (feature `desktop` off) | The same egui editor, tools, panels and theme used on macOS. The iPad host drives `App::frame`; the eframe lifecycle, `rfd` and the macOS menu stay behind `desktop`. |
| Pure input/controllers | `crates/onecad-interaction` | Contact ownership, sample chronology, prediction replacement, gesture arbitration (`touch` module), tool sessions, drafts, snapping and recognition. No UI toolkit. |
| Application authority | `crates/onecad-app` | The only document writer: `DocumentRuntime`, fenced commits, persistence, worker supervision behind `WorkerHost`. No UIKit/egui/wgpu. |
| Embedded kernel link | `crates/onecad-embedded-worker` | `extern "C"` declarations for worker C ABI v3 and the link of the static worker + OCCT + PlaneGCS archives. Nothing else. |
| Kernel | `worker/` (`onecad_worker_lib`) | OCW1/MESH1 semantics, unchanged wire. |

Swift never holds a second document model, history or undo stack. A visible
button never establishes tool support; every command goes through the same Rust
services as macOS.

## Worker backends (`onecad-app` features)

| Feature | Default | Meaning |
|---|---|---|
| `sidecar` | yes | `SidecarHost`: spawn `onecad-worker`, release manifest SHA-256 + hello checks, SIGKILL wedge remedy. Requires `tokio/process` and `trash`. |
| `embedded-kernel` | no | `InProcessHost`: C ABI v3 on a dedicated thread over a `socketpair`, embedded kernel identity checks. Requires `onecad-embedded-worker`. |

- `target_os = "ios"` with `sidecar` is a compile error; iOS without
  `embedded-kernel` is a compile error. Both may be enabled on macOS for
  tests; production selection is explicit (`WorkerBackend`), never implicit.
- Shared across both: handshake, `verify_hello`, solver-policy check,
  request mapping, `workerEpoch` and `expectedBaseHash` fencing, poison keys,
  discard tracking and `stream_plan` gates. Only *launch*, *exit observation*
  and *termination* differ (`WorkerHost` / `WorkerInstance`).
- Release identity:
  - Sidecar: `packaging/binaries/onecad-worker-manifest.json` (manifest v1,
    binary SHA-256). Unchanged.
  - Embedded: `onecad-embedded-kernel.json` (manifest v2, `kind:
    "embedded"`), generated by the worker CMake build for the exact target and
    SDK, embedded by `onecad-app/build.rs` when `embedded-kernel` is on.
    Contains ABI version, worker/protocol/quantization/solver-policy versions,
    OCCT version, build id, platform, deployment target and the OCCT
    fingerprint (`hex16(fnv1a(seed))`, same seed rule as the worker). The
    archive SHA-256 is recorded for provenance. Release builds fail when the
    file is missing or names another platform. At start the host checks
    `onecad_worker_abi_version() == 3` and verifies the hello against it.
- Fingerprints differ between macOS and iPad builds. They key disposable
  caches and poison entries only; `.onecad` documents stay portable and are
  regenerated when caches are stale.

### In-process failure policy

- Shutdown is cooperative: send `Shutdown`, close the host socket end, await
  the run thread's exit signal for a bounded grace.
- A wedged or unresponsive in-process worker cannot be killed. The instance is
  **abandoned once**, the supervisor enters `Failed` with reason
  `relaunch-required`, stops scheduling kernel work, and the UI shows a
  terminal relaunch-required state. No replacement thread is started; there is
  no restart loop. Durable state is protected by the normal autosave path.
- Kernel crash = app crash. The worker-side journal (ABI 3 `journal_cb`) writes
  `<app_support>/kernel-journal/inflight.json` (temp + rename, no fsync, see
  durability below) before each job and plan op, and removes it after the
  terminal frame is written. On launch a leftover record is a *suspected*
  interruption: its poison key gets one strike in
  `<app_support>/kernel-journal/poison.json`; at the in-process threshold the
  plan circuit for that key opens and regeneration stops before that op until
  the user clears it. Termination, jetsam or backgrounding never poison an op
  on their own without a leftover op record, and a record older than the
  current fingerprint is discarded.
- Durability: journal writes are best effort (rename without fsync); a failed
  journal write is logged, counted, surfaced in worker status and does not
  block the op. Document saves use the existing atomic container writer
  (temp + `sync_all` + rename + directory fsync). Save status names the latest
  durable revision; accepted but unsaved edits may be lost on process loss and
  autosave recovery offers the latest autosave.

## C ABI (`crates/onecad-ios/include/onecad_ios.h`)

- `ONECAD_IOS_ABI_VERSION` is bumped on any signature or struct change; every
  struct starts with `uint32_t struct_size` and older/smaller structs are
  rejected.
- One opaque `onecad_ios_app*` per process. **All functions except
  `onecad_ios_abi_version` must be called on the thread that created the app
  (the UIKit main thread)**; other threads get `ONECAD_IOS_ERR_WRONG_THREAD`.
- Every exported function catches Rust panics (`catch_unwind`) and returns
  `ONECAD_IOS_ERR_PANIC`; after a panic the app is poisoned and only `destroy`
  succeeds. C++ exceptions never cross the worker ABI (the worker entry points
  are `noexcept`).
- Inputs are copied before the call returns; no UIKit object or borrowed
  pointer is retained. Output pointers returned by the app (accessibility
  snapshot, host requests, strings) stay valid until the next call of the same
  function or `destroy`; strings returned with `_string_free` ownership must be
  freed by the host.
- The `wake` callback may be invoked from any thread at any time after create
  and before destroy returns; it must only schedule a frame on the main thread.
  `destroy` stops all producers before returning, so no callback is invoked
  after it returns.
- Bounded queues: input samples (4096 per batch, 16384 pending), host requests
  (64). Overflow returns `ONECAD_IOS_ERR_OVERFLOW` and coalesces only disposable
  movement; begin/end/cancel are never dropped.
- `test-hooks` (nondefault cargo feature, Xcode `Acceptance` configuration
  only) adds `onecad_ios_test_*` functions: trace replay through the same input
  entry point, semantic queries (mass properties, history, constraints) and
  fault injection. Release and Debug products must not export any
  `onecad_ios_test_` symbol; the simulator gate checks this with `nm`.

## Rendering

The shared renderer runs with `RenderProfile::Mobile` on iPad and `Desktop` on
macOS: sub-native scene image on large drawables (3 Mpx cap, scale 0.5–1),
no screen-space ambient occlusion, half-size IBL cubes, Xray targets only while
Xray is shown, no SSAA; 4× MSAA on both. egui overlays and picking stay at the
display scale. One window's display memory is one budget: the shared renderer's
allowance reserved for the active document (448 MiB on iPad, 512 MiB on macOS,
replacement overlap included) plus 64 MiB for parked tabs' disposable caches.
Parked caches are thumbnails plus each parked document's prepared CPU geometry;
on iPad they are evicted oldest first when over their share, on macOS kept.
Backgrounding releases the renderer's targets; a memory warning releases parked
caches (and, in the background, retries a refused target release) and may lower
the scene scale. Figures, lifecycle and the exact target
arithmetic: [HOST.md](HOST.md#rendering-profile-and-display-memory). They are
payload estimates; device memory, frame rate and thermals are physical-device
evidence (class 6).

## Threads

| Thread | Work |
|---|---|
| UIKit main | All ABI calls, egui frame, wgpu surface acquire/present, `UITouch` copying, accessibility. Never waits on kernel, file I/O or worker shutdown beyond the bounded destroy grace. |
| Tokio service runtime (4 workers) | `onecad-app` services, document runtime, scheduling, saves. |
| `onecad-worker` (8 MiB stack) | `onecad_worker_run_config`; the worker spawns its own kernel/solver/status lanes. |

## Input contract (summary; types in `onecad_ios.h` and `onecad-interaction::touch`)

- Each sample: contact id, kind (finger, pencil, indirect pointer), phase,
  provenance (actual, coalesced, predicted, estimated-update), monotonic
  timestamp, logical-point position, presence mask for force, altitude,
  azimuth, roll and hover height, estimation index, and the view/transform
  generation it was captured in.
- Actual and coalesced samples are delivered in chronological order and the
  final coalesced sample equal to the actual touch is not duplicated.
  Predicted samples replace earlier predictions for the contact and only drive
  transient overlays; they never reach authoring.
- One routing owner per contact. Pencil contacts own authoring and selection;
  finger contacts own navigation and controls. Pencil never synthesizes a
  second mouse click.
- Unavailable optional data stays unavailable; core workflows require no
  pressure, hover or Pencil Pro feature.

## Qualification policy

Evidence classes are never merged:

1. Rust pure/component tests (macOS host).
2. Synthetic Pencil replay through the production input boundary (labeled
   synthetic; not physical Pencil evidence).
3. Native XCTest in the simulator with the real in-process kernel.
4. Public XCUITest of the real app.
5. Unsigned generic-device Release build: compile/link only.
6. Physical-device evidence (ONECAD-469), required for Pencil pressure, hover,
   palm rejection, latency, GPU, memory, thermals, jetsam and release.

`cargo xtask ios-simulator-gate <dir>` produces and verifies classes 2–5. See
[TESTING.md](TESTING.md).
